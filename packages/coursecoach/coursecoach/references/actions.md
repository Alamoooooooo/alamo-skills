# 主页按钮与动作篮协议

课程主页是**纯静态 HTML**（双击可用、无后端、无网络）。所以按钮不可能自己完成批改或生成——
它只做两件事：**攒动作**、**拼指令**。真正的执行永远发生在 AI 这一侧。

这不是妥协，是有意设计：静态页 + 文本指令 = 换任何 agent 都能跑，不依赖 MCP、不依赖本地服务。

## 1. 页面上有什么按钮

| 位置 | 按钮 | 动作类型 `k` | 载荷 |
|:--|:--|:--|:--|
| 章节底部 | 📖 补这一章讲解 / 重写讲解 | `lesson` | `nid` |
| 章节底部 | 📝 给这一章出作业 | `hw` | `nid` |
| 章节底部 | 🔗 补资料 | `research` | `nid` |
| 章节底部 | ☑ 本章全部知识点 | —（批量） | 展开成 N 条 `lesson` |
| 知识点标签 | 📖 生成讲解 / 📝 出题 / 🔗 补资料 | `lesson` / `hw` / `research` | `nid` + `term` |
| 作业行 | ✎ 批改 / 重批 | `grade` | `hw` |
| 动作篮 | 全选知识点 / 全选待批改 / 全选无作业章节 | —（批量） | — |

选中项存 `localStorage`（键 `coursecoach:<课程名>`），刷新不丢。点「复制指令」得到下面这种文本：

**动作篮的固定布局（改模板时别退化）**

- 整个篮子 `position:fixed` 钉在右下角，高度上限 `100vh - 40px`；页面正文自己滚，篮子不跟着跑。
- 篮子内部分三层：标题条 `⇅` 内容区 → 底部按钮。**只有中间的动作列表滚动**（`.list{overflow-y:auto}`），
  「复制指令 / 清空」始终贴在面板底部，不需要把面板拖到最下面才点得到。
- **动作一改，旧指令立即作废**：`commit()` 会清空指令框并收回复选框、把提示语恢复成默认，避免把上一次的指令粘出去。
- **从空到有自动展开**：动作篮为空时选中第一项（包括清空后重选），面板自动打开，直接看到「复制指令」。
- 面板收起时点标题条展开；清空后篮子自动隐藏。

```
/coursecoach 执行动作
课程：AI 全栈学习路线
目录：你的课程目录
共 5 项，按类型分组：

【批改作业】1 项
1) hw-stage0-vec

【生成/补充讲解】3 项
2) stage0-math · 知识点「向量与线性组合」
3) stage0-math · 知识点「矩阵乘法」
4) stage1-python（整章）

【出作业】1 项
5) stage2-attention（整章）
```

## 2. 收到指令后怎么执行

**先确认再动手**：一句话复述要做什么（"3 条讲解 + 1 份批改"），有歧义就问，不要闷头生成。

### 2.1 `grade` —— 批改

```
读 <目录>/homework/<hw>.md
→ 确认「我的作答」区非空（空则直接回复"还没作答"，不要凭空判分）
→ 按该作业 frontmatter 的 rubric 逐条判定，生成 result JSON
→ python scripts/grade.py --course <目录> --hw <hw> --result <json>
```

result JSON 结构见 `grading-rubric.md`。`grade.py` 会自动改写作业 frontmatter、写反馈区、回写 syllabus 掌握度、重跑 sync。
**批改后必须**：把分数、等级、最弱的那一条告诉用户，不要只说"已完成"。

### 2.2 `lesson` —— 生成 / 补充讲解

这是**唯一需要自己决定落盘位置**的动作，规则固定：

| 载荷 | 文件 | 说明 |
|:--|:--|:--|
| 只有 `nid`（整章） | `lessons/<nid>.md` | 整章讲义 |
| `nid` + `term`（单点） | `lessons/<nid>--<term>.md` | 单知识点讲解 |

`--` 是两个半角连字符，`term` 用知识点原文（中文原样保留，不转拼音、不转 slug），
因为 `sync.py` 就是按 `节点id--知识点原文` 匹配的，改名会失联。

frontmatter：

```yaml
---
title: 广播机制
node: stage0-math
point: 广播
kind: point          # point | chapter
updated: 2026-10-18
---
```

正文要求（这几条比字数重要）：

- **先讲为什么**，再讲怎么用。用户卡住的地方通常不是语法，是"设计动机"。
- 必须有一节「代价 / 局限」——只说优点等于没讲。
- 至少一个可手算 / 可跑的小例子，规模小到能在脑子里过一遍。
- 不要整段抄资料库链接；资料库是"去哪儿看"，讲义是"现在就懂"。
- 长度：单点 500–1000 字，整章 800–2000 字。超了就是没提炼。

写完跑一次 `sync.py`，主页上该章节会自动出现「📄 打开本章讲义」，知识点标签前多一个 📄。

链接协议由 `sync.py` 自动判定，**不要手写死**：课程在 vault 内（向上能找到 `.obsidian`）→ `obsidian://open?vault=<库名>&file=<相对路径>`，点了在 Obsidian 打开排版好的笔记且网页不跳走；在 vault 外 → `file://`，新标签页开原始 md。所以把课程挪进/挪出 vault 后只要重跑 `sync.py`，链接自己就对了。

### 2.3 `hw` —— 出作业

按 `assets/homework.template.md` 生成 `homework/hw-<节点id去前缀>-<slug>.md`，
frontmatter 的 `stage` 必须等于该节点 id（`sync.py` 靠它挂到章节上）。
题目数量、rubric 条数见 `grading-rubric.md`。出完用
`syllabus.py --course <dir> attach-hw --id <nid> --hw <hw-id>` 挂上，再 `sync.py`。

**不要顺手把答案写进去**。作业是给用户做的。

### 2.4 `research` —— 补资料

联网检索 → 只保留真读得懂的 3–6 条 → 追加到 `resources/资料库.md`（按节点分节）。
每条给：标题、链接、一句"它解决什么问题"。查不到权威来源就写「待核实」，不要编。

## 3. 批量怎么办

- **≤ 5 项**：一口气做完，逐项汇报。
- **6–15 项**：按类型分批，先 `grade` 再 `lesson`，每批结束报一次进度。
- **> 15 项**：先做前 5 项 + 给出剩余的执行顺序，让用户确认再继续。
  一次生成 100 篇讲义既慢又难核对，属于反模式。

同一节点的多条单点讲解，可以合并思路但**不要合并文件**——文件粒度就是复习粒度。

## 4. 执行完的收尾

1. `sync.py` 重编译（`grade.py` / 讲义写入后都要）。
2. 一句话汇报：做了什么、产出到哪、下一步建议。
3. 有实质结论（薄弱点、新增节点）才更新大纲；不要为了"有变化"而改。

## 5. 没有这个页面的 agent 怎么办

指令就是纯文本，任何模型都能读。页面上没有按钮时，用户直接说
「给 stage0-math 的『广播』出题」「批改 hw-stage0-vec」同样能触发同一套流程。
按钮是入口的便利，不是能力的前提。
