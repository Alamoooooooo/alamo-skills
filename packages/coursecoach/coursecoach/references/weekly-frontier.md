# 周更：让前沿进展真正落进课程

Phase 7 的周期性维护动作。**宿主负责排期，本文件规定"怎么干"**——因为排期能力因平台而异，而写回规矩必须在任何平台都一样。

触发方式：用户说「周更 / 这周有什么值得学的」，或宿主上的一条周更自动化。

## 1. 检索

按 8 个维度扫最近一周（`freshness=d7`），主题随课程变，维度可增删：

| 维度 | 关注什么 |
|:--|:--|
| 架构 | 新 backbone、注意力替代方案、混合结构、稀疏/MoE |
| 开放权重与发布 | 真放权重 vs 只放 API；许可证是否允许学习/商用 |
| 训练与后训练 | 新算法、新目标函数、被推翻的旧结论 |
| 强化学习 | RLVR / 偏好优化 / 奖励建模的新做法 |
| Agent 与编排 | 工具调用、上下文管理、多智能体 |
| 协议与标准 | MCP 之类协议的版本、破坏性变更 |
| 评测与复测 | 基准失效、独立复现翻车、榜单可信度 |
| 工程与效率 | 显存、推理成本、长上下文、量化 |

**宁少勿滥。一周有 0–3 条真增量是正常值**，收到 8 条基本说明判据放水了。

## 2. 判据

只有一条标准：**会不会改变他下周学什么**。

| 收 | 丢 |
|:--|:--|
| 说明课程里某节已过时 | 融资、估值、人事变动 |
| 值得新增一个知识点或专题 | 产品发布、营销话术 |
| 改变学习顺序或权重（该提前学） | 刷榜、无复现的宣称、榜单第一名 |
| 补齐课程明确标注「待补」的空白 | 和课程主题无关的行业新闻 |

**只有厂商自评、没有第三方复现的东西**，可以记进资料库并标 `⚠️待核实`，但不能当结论写进 syllabus。

## 3. 写回（唯一写入口，硬规矩）

先读现状，再增量写回。**不读就写等于删除**。

| 要加什么 | 用什么 | 陷阱 |
|:--|:--|:--|
| 知识点 | `syllabus.py --course <dir> set-points --id <nid> --points "旧1,旧2,…,新"` | **整表覆盖**。必须把原有知识点全部带上重新传一遍，漏一个就是删一个 |

**挂概念卡时两个入口的写法不一样，别混**：

- **命令行** `set-points` 写 `标签|卡片名`，**只写卡片名**，脚本自动补 `20-概念/`。写全路径会得到 `20-概念/20-概念/…` 双前缀——不报错，只是点进去找不到卡片，静默退化成筛选。
- **手改 frontmatter** 时相反，`note` 字段要写全路径 `20-概念/卡片名`。

不写 `|` 也行：标签与卡片同名时会自动匹配上，匹配不到就是不可点（点击退化为按该词筛选），不报错。
| 新节点 | `syllabus.py --course <dir> add-node --id <nid> --title <t> --prereqs <先修> --points "…" --weeks 2 --summary "…"` | 先修必须已存在否则报错；新节点 `mastery` 自动为 null |
| 周数 | `syllabus.py --course <dir> set-weeks --id <nid> --weeks 2`（或 `2,2.5,4`） | 顺序是「冲刺,标准,长线」；改完核对三档总周数 |
| 资料 | 直接编辑 `resources/资料库.md`，按阶段分组追加 | 每条写清：链接 + 一句话用途 + 代价 + 核实日期 + `✅已核实` / `⚠️待核实` |
| 阶段笔记 / 概念卡 | Write 到 vault 对应目录 | 必须 `[[双链]]` 回挂索引页，否则成孤儿；表格内双链写 `\|` |

**禁止**（都是"看起来能改、其实一改就废"的那类）：

- ❌ 手改 `课程主页.html` —— 编译产物，下次 `sync.py` 全量覆盖
- ❌ 手写 `mastery` —— 只有 `grade.py` 能回写；周更没看过他的作答，无权打分
- ❌ 手改作业的 `review_due` —— 归 `review.py`
- ❌ 只改 syllabus 正文里的数字不改 frontmatter —— 页面只认 frontmatter

## 4. 收尾

1. 跑 `sync.py --course <dir>`，确认末尾零 `[warn]`（`set-points` 等命令其实会自动触发一次，显式跑一遍不亏）
2. 往 vault 写过笔记 → 做双链自检（收集全部文件名 → 抓 `[[ ]]` → 比对，排除围栏代码块与行内代码，表格里的 `\|` 先还原成 `|`）
3. 汇报，**≤5 行**：本周新增什么 / 为什么值得 / 改了哪些文件 / 对下周节奏的具体建议
4. 没有增量就直说「本周无实质增量」并列出扫过的维度。**不要为了有产出而硬塞**

## 5. 排期：交给宿主，只做薄壳

skill 无法给自己排期，自动化也不随课程文件夹走。所以：

```bash
python <skill>/scripts/schedule.py --course <course-dir> --kind weekly --json
```

脚本输出完整的 `name / scheduleType / rrule / prompt / cwds`，agent 拿它调宿主的 `automation_update`。

**不要手写 prompt**。手写一次就会有两个版本，之后路径、脚本名、参数一改，文档和实际任务就开始分叉——这是最容易发生、又最不容易发现的腐烂。脚本里的 prompt 是唯一来源，且自带正确的 skill 路径与解释器路径。

幂等：名字里带课程标题（`「课程名」· 前沿周更`），建之前先 list 按 name 比对，已存在就跳过。

迁移到别人的机器只有两步：装 skill → 进课程时跑一次 `schedule.py --check`，缺的补建。没有自动化能力的宿主怎么降级，见 `delivery.md` §5.2。

## 6. 边界：一门课只有一个权威源

课程可能同时存在多套"看板"（母版方案、手维护的路线图 HTML、vault 阶段笔记）。
周更**只认 `syllabus.md` 与其编译产物**。若用户还在维护另一套，先问清哪套是权威源：

- 若 `syllabus.md` 是权威源 → 其他看板要么归档，要么从 syllabus 派生，**不要双向手改**
- 若另一套才是权威源 → 本课程等于影子副本，周更应停下并让用户决定是否合并

两套并行维护、互相"同步"，是这类系统最常见的腐烂方式：数字对不上，谁也不知道哪个对。
