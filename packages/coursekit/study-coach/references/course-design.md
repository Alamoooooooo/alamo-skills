# 课程设计方法论

## Phase 1 澄清问题清单

一次最多问 4 个，优先问前 4 项：

1. **方向 / 主题**：具体想学什么？（越具体越好：不是「AI」，而是「做 AI Agent 开发」）
2. **目标程度**：了解即可 / 能动手做 / 能教别人。
3. **现有基础**：已会什么、明确不想重复什么。
4. **可投入时间**：每天几小时 → 决定强度档位。

可选追问：资源形态偏好（视频 / 论文 / 动手项目）、语言、是否要作业与项目产出。

## 阶段拆解

用「目标 → 能力 → 知识点 → 验收」四级拆：

1. 由目标倒推需要哪些**能力**。
2. 每项能力拆成若干**知识点**（一个节点一个主题，别太粗也别太碎）。
3. 每个节点写一条**可验证的验收**（能画出来 / 跑通 / 解释设计动机）。
4. 标注节点间**先修关系**，形成有向图（允许分叉，不强制一条直线）。

## 周期档位

| 档位 | 每周投入 | 适合 |
|---|---|---|
| 冲刺 | 20–25 h | 每天 3 h 以上 |
| 标准 | 12–15 h | 每天 2 h |
| 长线 | 8 h | 每天 1 h |

周期 = 总学时 / 每周投入，向上取整。周期数字要同时体现在 syllabus 正文与主页（sync 会渲染节点，周期写在正文）。

## 验收标准

- 坏：「读完第 3 章」。
- 好：「白板上手推反向传播，不查资料」「看到张量运算式能说出结果形状」「能解释为什么最小化交叉熵等价于最大似然」。

## 资源选择

- 一手来源优先：论文、官方文档、实验室工程博客。
- 课程只用来补概念，不追课；**不囤课**。
- 每条资源标：来源、日期、用途、代价（时间 / 难度）。
- 搜索所得不确定的内容标「待核实」。

## 反模式

- 一次生成 20 个阶段、每阶段 10 个知识点 → 用户直接放弃。
- 只有「学习」没有「验收」→ 无法判断是否学会。
- 大纲扁平列表、无先修 → 无法动态演化。用 Skill Graph。
