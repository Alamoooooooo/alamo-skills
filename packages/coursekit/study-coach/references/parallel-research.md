# 并行调研协议（Parallel Research）

课程阶段多于 6 个、或需要深入多个前沿领域时，串行 WebSearch 会拖慢生成。此时派子 Agent 并行调研，主 Agent 只做**裁决与落盘**。

## 何时启用

- 阶段数 ≥ 6 且每阶段都要找资源 → 并行。
- 单一阶段但涉及多个子领域（如「后训练」含 DPO / GRPO / RLVR / 蒸馏）→ 可拆 2–3 个子 Agent。
- 只需补一条资料 → 不要派，直接搜。

## 切分原则

| 原则 | 说明 |
|---|---|
| 按阶段切，不按关键词切 | 一个子 Agent 负责 1–3 个相邻阶段，保证它理解上下文 |
| 每个子 Agent 自包含 | 它看不到主对话，必须把主题、目标程度、阶段标题、已有资料全部写进 prompt |
| 限制搜索次数 | 每个子 Agent 3–5 次 WebSearch 足够，避免烧时间 |
| 统一输出格式 | 否则汇总时无法比对 |
| 明确禁区 | 不要它写文件、不要它改大纲、不要它编造链接 |

## Prompt 模板

```
你是「<课程主题>」课程的资源调研员。学习者背景：<已有基础>。目标程度：<了解 / 能动手 / 能教别人>。

请只调研以下阶段，找出 2026 年当下**仍然有效**的学习资源（宁少勿滥）：
- <阶段 N：标题> —— 需要覆盖：<知识点 1/2/3>

每个阶段输出 3–5 条资源，每条严格按此格式：
- 名称 | 类型（课程/书/论文/文档/项目） | 链接 | 为什么适合 | 代价或前置要求 | 信息日期

要求：
1. 优先官方文档、原论文、维护活跃的开源项目；排除营销页与搬运站。
2. 无法确认发布时间的，标注「日期待核实」。
3. 不要写文件、不要生成大纲、不要给学习计划 —— 只返回资源清单。
4. 结尾用一句话指出这个阶段最容易踩的坑。
```

## 汇总与裁决（主 Agent 必做）

1. **去重**：同一资源被多个子 Agent 提到，只留一次并合并理由。
2. **查真**：对关键资源抽查链接可用性；不确定的标「待核实」，不硬写。
3. **排序**：按「权威性 × 上手成本 × 与目标的贴合度」排，不按子 Agent 的报告顺序。
4. **裁剪**：每阶段最终保留 3–5 条。**这是裁决，不是拼接** —— 子 Agent 给 20 条，教材里不能有 20 条。
5. **落盘**：写进 `resources/资料库.md`，按阶段分节，标来源与日期。

## 失败与降级

| 情况 | 处理 |
|---|---|
| 无法派子 Agent | 退回串行 WebSearch，每阶段 1–2 次，仍要标日期 |
| 子 Agent 返回空 / 跑偏 | 换更具体的 prompt 重派一次；仍失败则主 Agent 自己搜 |
| 结果互相矛盾（如某框架已弃用） | 以官方仓库最新 release / 文档为准，并在资料里注明分歧 |
| 网络不可用 | 用已有知识 + 明确标注「未经联网核实，需复核」 |

## 反模式

- ❌ 派 14 个 Agent 各搜 10 次 —— 成本爆炸，收益递减。
- ❌ 把子 Agent 的报告原样贴给用户 —— 你才是裁决者。
- ❌ 子 Agent 结果不查真就落盘 —— 会写进失效链接。
- ❌ 让子 Agent 直接改 syllabus —— 并行写同一文件必然冲突。
